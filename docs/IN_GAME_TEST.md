# In-game test checklist — 0.5.2

**New build: client tests pending.** Offline results are separate from client behavior. Record date, client version/build/interface, character, zone, UI scale and Lua/taint output with the observed results.

The 0.5.2 offline suite passes 190 counted behavioral cases, four fresh-startup visibility combinations, separate banner/startup/reload/missing-API checks and 54 static selftests. All 13 addon Lua files load under Lua 5.1; 28 C API members are reviewed, with zero forbidden mutations or invalid IDs. The 16-file, 75,870-byte package builds. The detailed record is in [TECHNICAL_NOTES.md](../TECHNICAL_NOTES.md). None of those stubs establishes the client checks below. Record the actual installed build and observed results here.

## Install and initial selection

1. Replace the installed `QuestreihenTracker` folder with the 0.5.2 release package. If upgrading from 0.3.1 or earlier, remove the previous addon folder too; that identity change starts fresh preferences. Later upgrades must retain saved chat/screen-warning choices, including the screenshot's chat **Aus** state. Without valid saved settings, expect chat, screen and keep-open **An** in the gear panel. Confirm `QuestData.lua` is absent. Compare the fourth `GetBuildInfo()` result with TOC 120100, enable Lua errors and `/reload`.
2. With fresh preferences or an old curated selection, the tracker starts closed. Open `/qrt`. Expect **Keine Questreihe ausgewählt** and no installed stories. Empty/missing zone data must remain empty/loading, not select an invented story.
3. Choose a supplied current-zone line. Confirm actual quest membership and localized titles. Complete objectives without hand-in: status remains **Angenommen**. Handed-in quests show **Abgeschlossen**.
4. Leave the zone and `/reload`. A saved runtime selection should reload its map/line from the game. No saved progress or titles may override current character state.

All must remain usable at minimum/default size and another UI scale. Open/close settings repeatedly and close the main window with settings open; settings must not remain stranded onscreen.
2. With keep-open **An**, open the tracker and talents. The tracker must remain visible. Close/reopen talents, try the spellbook and map, and press Escape. Escape must not dismiss the main tracker in this mode; auxiliary dialogs can close normally. Repeat in/out of combat and record any Lua/taint issue.
3. While the tracker is open, use a teleport/portal, a hearthstone and a normal zone/loading transition. Record the methods and exact results. Once normal UI display returns, the main tracker must retain its opening choice and position. It must not be permanently closed by these transitions.
4. With the tracker open and keep-open **An**, run `/reload`. It must reopen with its previous geometry and saved line. Repeat with loading or no selected line. Missing quest data must not stop opening or manufacture a list.
5. Close deliberately using X, `/qrt` and minimap left-click in separate runs. Each must close the tracker even with keep-open **An**. Open talents, teleport and `/reload` after each close: it must stay closed until explicitly opened again. Repeat while **Verfolgte Quest** is waiting for data; late lookup replies must not reopen the deliberately closed tracker. A hidden tracker must not repeatedly reopen on quest/data events.
6. Switch keep-open **Aus** while open. Ordinary Escape/game-panel closing must be allowed; `/reload` must start closed. Explicitly reopen it, switch keep-open **An** and repeat reload: the enabled setting must restore the explicit open choice. Changing keep-open must not alter either warning preference.
7. Check all three settings after close/reopen and `/reload`, then after **Entfernen**. Their independent choices must persist. Drag the settings panel, close/reopen and reload; its saved position must be retained. `/qrt reset` restores default settings and geometry and closes the tracker without changing quests, watches or navigation. After reset, reload must keep the tracker closed until explicitly opened again.

## Automatic active-quest scrolling

1. Select a long runtime line with an accepted quest outside the initial viewport. On showing the line, the active quest must be visible and the scrollbar must reflect the actual position. Repeat for an active row near the beginning, middle and end; no offset may exceed the scroll range.
2. With several active members, record the initial order. Without a newer target, expect the first active member in supplied order. Explicitly click another active member and refresh: it becomes the preferred target while still active. Newly accept a different member through normal gameplay: the newly accepted quest should become visible and take priority. Click a different active member again: that newer explicit choice becomes the target. The scroll operation itself must not add watches or set Blizzard navigation.
3. Scroll away manually, then allow a normal log/data refresh. If the target is now offscreen, the list must bring it back into view. If the target is still fully visible after manual scrolling, the refresh must retain the position. Mouse-wheel and scrollbar input must remain usable between updates.
4. Complete objectives without hand-in: the quest remains active. Test a currently accepted repeatable member with historical completion: it must still be a scrolling target even if the existing progress color/status reflects the earlier completion. Hand in or abandon the current target through Blizzard's normal controls; confirm selection moves to another active member if one exists. With no active member, there must be no invented target, jump loop or quest mutation.
5. Test wrapped two-line German titles, delayed title data, minimum 320 × 300/default 360 × 500 sizes, larger sizes and another UI scale. Resize so the selected row falls outside the new viewport: the target must remain visible where the viewport allows it, with correct row height, scrollbar, no clipped status or excessive blank scroll space.
6. Change/remove the displayed line, then select another and `/reload`. No previous line's target may force an unrelated scroll position. Switch lines during delayed data/acceptance updates and confirm only active members of the currently displayed line are targets.
7. Scroll with the mouse wheel and scrollbar after automatic positioning. Both must remain usable, and row clicks/dividers/resize grip must not overlap the scrollbar. Record actual rendered results and Lua/taint output.

## Warnings

Use normal gameplay. Only an explicit quest-row left click may add a watch and set the quest navigation target; events, refreshes and lookup must not set navigation. No automatic acceptance or abandonment is permitted.

Use the gear panel for the warning switches below. They should no longer occupy separate rows in the main window. Keep-open is independent of both warning outputs.

1. With a loaded selected line, **Chatwarnung: An** and **Bildschirmwarnung: An**, enter an unrelated world-quest area. Expect one warning box and a local chat warning. No duplicate addon warning text may appear above the box through Blizzard's error frame. Stay in the area and progress it: unchanged activity must not repeatedly warn. Leave/re-enter: a new warning is allowed.
2. Repeat with an actual open-world bonus objective. Record its quest ID, task/area state and displayed title. Scenario-only bonus steps without quest IDs are outside the quest-membership comparison.
3. In the quest log, right click a different quest → **Quest beobachten**. Expect a warning. Remove/re-add the watch and test rapid toggles. Existing watches at login should not produce a flood.
4. Select an unrelated quest for the navigation arrow using Blizzard's side tracker. Expect a warning. Choose another target, then return. A nonquest waypoint/map pin with a retained quest ID must not produce a quest-navigation warning.
5. A selected-list quest must never warn. No selected list or a loading list must suppress classification. Warning wording compares the supplied membership only.
6. Observe a normal accepted unrelated quest: warn once current log membership is confirmed. Repeated/delayed acceptance events must not spam. Watch/task/navigation events in the same refresh should not duplicate the same quest.
7. Check temporary missing title data uses an ID fallback, delayed data does not imply exit/re-entry, and removal/turn-in/selection changes cancel stale pending warnings.
8. Compare the prominent banner's duration with a separate normal Blizzard error message: it should stay twice as long and must not generate a native addon duplicate. Check long German titles and a hidden tracker. Trigger a log update during display and verify prompt refresh, then expiry without repeated warnings. Changing/removing the selection clears the old banner.
9. With screen warnings enabled, click **Chatwarnung: An** and confirm **Chatwarnung: Aus**. Leave/re-enter an unrelated task area or otherwise trigger a new warning: the box must still appear, with no activity-warning message in chat. Other local diagnostic/click-failure messages may still appear. Toggle chat **An** again without changing activity: old warnings must not replay. Trigger a new activity and confirm chat output returns.
10. While a box is visible, click **Bildschirmwarnung: An** and confirm **Bildschirmwarnung: Aus**. The box must disappear immediately. With chat enabled, trigger a new activity: chat must warn while the box stays hidden. Disable both outputs and trigger another activity: neither activity-warning output may appear. Re-enable either output without changing activity: no old warning may replay. New activity must use only the enabled output.
11. Test all four combinations of chat/screen **An/Aus** through close/reopen, `/reload`, selection changes and **Entfernen**. Both labels and behavior must retain their independent choices. `/qrt reset` restores both to **An** and changes only addon preferences. Disable the screen output during a pending refresh and confirm quest progress still updates promptly.
